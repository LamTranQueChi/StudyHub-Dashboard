## 1. GIỚI THIỆU ĐỀ TÀI

**Tên đề tài:** Tìm hiểu về JavaScript DOM và xây dựng trang Dashboard học tập.

StudyHub là website hỗ trợ sinh viên theo dõi và quản lý quá trình học tập. Hệ thống được xây dựng nhằm vận dụng kiến thức HTML, CSS và JavaScript DOM vào việc thiết kế giao diện, xử lý sự kiện và xây dựng các chức năng tương tác trên website.

Đề tài tập trung tìm hiểu cách JavaScript DOM thao tác với các thành phần HTML, xử lý sự kiện và xây dựng một trang Dashboard học tập có giao diện thân thiện, trực quan và dễ sử dụng.

Bên cạnh việc xây dựng giao diện Frontend, đề tài còn tìm hiểu cách xây dựng Backend, kết nối API và lưu trữ dữ liệu nhằm hoàn thiện một ứng dụng web.

## 2. MỤC TIÊU ĐỀ TÀI

- Tìm hiểu cấu trúc và nguyên lý hoạt động của JavaScript DOM.
- Nắm vững cách truy xuất, thay đổi và thao tác với các phần tử HTML.
- Vận dụng JavaScript để xử lý sự kiện và xây dựng các chức năng tương tác.
- Xây dựng giao diện Dashboard hỗ trợ quản lý và theo dõi học tập.
- Tìm hiểu cách kết nối Frontend với Backend thông qua API.
- Tìm hiểu cách sử dụng Node.js, Express.js và SQLite.
- Triển khai website để người dùng có thể truy cập và trải nghiệm.

## 9. TRIỂN KHAI BACKEND LÊN RENDER

Backend sử dụng Node.js, Express.js và SQLite, được triển khai thông qua Render Web Service.

### 9.1. Tạo Web Service

1. Truy cập Render.
2. Chọn **New → Web Service**.
3. Kết nối tài khoản GitHub.
4. Chọn repository `StudyHub-Dashboard`.

**Cấu hình các thông số:**

| Thuộc tính | Giá trị |
|---|---|
| Root Directory | `backend` |
| Runtime | Node |
| Build Command | `npm install` |
| Start Command | `npm start` |

### 9.2. Cấu hình Environment Variables

| Tên biến | Giá trị |
|---|---|
| `NODE_ENV` | `production` |
| `JWT_SECRET` | Chuỗi bí mật ngẫu nhiên tối thiểu 32 ký tự |
| `FRONTEND_ORIGINS` | Origin của website GitHub Pages |
| `DATABASE_PATH` | `/var/data/studyhub.sqlite` |

**Lưu ý:** Không công khai giá trị thực tế của `JWT_SECRET` trên GitHub.

### 9.3. Cấu hình Persistent Disk

Để tránh mất dữ liệu SQLite khi dịch vụ được triển khai lại, cần cấu hình Persistent Disk trên Render.

**Mount Path:**

```text
/var/data
```

Database sẽ được lưu tại:

```text
/var/data/studyhub.sqlite
```

### 9.4. Kiểm tra Backend

Sau khi Deploy thành công, truy cập:

```text
https://TEN-SERVICE.onrender.com/api/health
```

Nếu API trả về JSON có giá trị `"ok": true`, Backend đã hoạt động.

**Backend URL:**  
Chưa cập nhật – bổ sung sau khi Render cấp URL thực tế.

## 10. KẾT NỐI FRONTEND VỚI BACKEND

Sau khi triển khai Backend lên Render, cần cập nhật địa chỉ API trong file:

```text
js/config.js
```

Tìm dòng cấu hình:

```javascript
const productionApi = "https://YOUR-STUDYHUB-BACKEND.onrender.com/api";
```

Thay thế bằng URL Backend thực tế do Render cung cấp.

**Ví dụ:**

```javascript
const productionApi = "https://studyhub-api.onrender.com/api";
```

**Sau khi cập nhật:**

1. Lưu file `config.js`.
2. Thực hiện Git Add, Commit và Push.
3. Chờ GitHub Pages cập nhật phiên bản mới.
4. Truy cập website và kiểm tra kết nối API.
5. Kiểm tra chức năng đăng nhập và các chức năng liên quan đến dữ liệu.

**Lưu ý về CORS:**

Biến `FRONTEND_ORIGINS` trên Render cần được cấu hình đúng origin của GitHub Pages.

Ví dụ:

```text
https://LamTranQueChi.github.io
```

Không thêm đường dẫn tên repository vào giá trị origin.

## 15. LƯU Ý KHI SỬ DỤNG HỆ THỐNG

- GitHub Pages chỉ triển khai Frontend, không chạy trực tiếp Node.js hoặc SQLite.
- Backend cần được triển khai và hoạt động trên Render để các chức năng sử dụng API hoạt động.
- Không đưa file `.env`, `JWT_SECRET`, `node_modules` hoặc database SQLite đang sử dụng lên GitHub.
- File `backend/data/studyhub.sql` được sử dụng làm dữ liệu nguồn để khởi tạo database khi triển khai lần đầu.
- Nếu đã có database trên Persistent Disk, Backend giữ lại dữ liệu hiện tại khi khởi động lại và không tự ghi đè bằng dữ liệu SQL ban đầu.
- Lịch học là dữ liệu minh họa phục vụ kiểm thử giao diện, không phải thời khóa biểu chính thức.

- Chức năng nằm ngay trong thẻ **Tỷ lệ chuyên cần** của trang Hồ sơ sinh viên, sử dụng các file hiện có; không tạo `chuyencan.css` hoặc `chuyencan.js`.
- Tổng số buổi được đếm từ `class_schedule_sessions` theo lớp và học kỳ đã chọn. Chỉ tính các buổi đã kết thúc theo múi giờ `Asia/Ho_Chi_Minh`.
- Khi chưa có dữ liệu điểm danh chính thức, sinh viên có thể tự khai báo số buổi vắng và xác nhận tính trung thực.
- Vắng có phép hay không phép đều được tính là một buổi vắng.
- Công thức:

  \[
  \text{Tỷ lệ chuyên cần} =
  \frac{\text{Tổng buổi đã diễn ra} - \text{Số buổi vắng}}
  {\text{Tổng buổi đã diễn ra}} \times 100\%
  \]

- Nếu đã có bản ghi điểm danh chính thức trong bảng `attendance`, hệ thống ưu tiên dữ liệu đó và không cho khai báo cá nhân ghi đè.
- Số liệu tự khai báo chỉ dùng để tự theo dõi; không thay thế dữ liệu điểm danh chính thức của Trường Đại học Trà Vinh. Dự án hiện đếm từ thời khóa biểu đã được lưu/đồng bộ vào StudyHub, không tự nhận là đang truy vấn trực tiếp cổng điểm danh của trường.

### 17.4. Kiểm tra sau khi cập nhật

1. Khởi động Backend theo hướng dẫn trong `backend/README.md`.
2. Đăng nhập bằng tài khoản sinh viên.
3. Chọn học kỳ đang có thời khóa biểu.
4. Mở **Sinh viên** → thẻ **Tỷ lệ chuyên cần** → bấm dấu `i` để xem cách tính.
5. Chọn **Khai báo buổi vắng**, nhập số buổi, tích xác nhận trung thực và lưu.
6. Chuyển VI/EN để kiểm tra hộp thoại, thông báo và bảng.
